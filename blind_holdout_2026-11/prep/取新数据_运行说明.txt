    - 必须带 --no-deps：baostock 只依赖 pandas，环境里已有。不带的话 pip 会把 pandas、numpy 也装进 pylibs\（一百多 MB），并且会盖过环境里的 numpy。
    - 0.9.1 是旧项目环境里用过的版本（摘要 B4）；PyPI 上若没有这个版本号，去掉 “==0.9.1”。
    - 装完核对（不联网）：PY -I -X utf8 -c "import sys; sys.path.insert(0, r'<BLIND_ROOT>\pylibs'); import baostock; print(baostock.__version__)"

  第 1 步  用一只股票验证接口（联网；3 次请求，几秒；不写任何文件）
      PY -I -X utf8 prep\fetch_baostock_range.py --start 2026-09-21 --end 2026-11-09 --dry-run-one
    看输出：
    - 没有 AssertionError（字段名与脚本里写的一致）；
    - trade calendar 一行：2026-09-21 至 2026-10-09 应是 9 个交易日（09-21、22、23、24、28、29、30、10-08、10-09），10-12 起每个工作日一天；
    - CHECK 1 为 True（两次请求的日期与交易日历相同）；
    - CHECK 2 每行为 True（成交额 ÷ 成交量落在最低价与最高价之间，说明成交量单位是股）；
    - CHECK 3：tradestatus 只有 '1'（或含 '0'）、isST 只有 '0'/'1'、日期形如 2026-09-21；
    - CHECK 4 人工看一眼：preclose 等于前一日收盘；turn 是百分数；该股区间后没有除权时 qfq 行与原价行相同。
    任何一项不对就停，把输出交回，不要改脚本硬跑。

  第 2 步  全量取数（联网；2–3.5 小时；可中断，重跑同一条命令续跑）

    - --start 2026-09-21 是为了与旧面板留出 9 个重叠交易日；不要改小重叠。
    - --end 取“北京时间 18:00 已过”的最后一个交易日（Baostock 当日 17:30 入库日线、18:00 入库复权因子）。本地时间每天 02:00 以后，北京当天的数据才算齐。

    - 输出：data_new\raw\<代码>.csv（3,329 个）、data_new\trade_dates.csv、data_new\fetch_log.txt（每只一行：进度、行数、速度、预计剩余）、data_new\fetch_meta.json。

六、常见失败与处理
  - FileExistsError …\data_new\fetch.lock：上一次运行还在，或被强行结束后锁没删。确认没有别的取数进程后手工删掉 fetch.lock 再跑。
  - login failed，或 “attempt k of 4 failed” 反复出现（Baostock 网络错误，旧记录里出现过 10002007）：脚本每只最多重试 3 次、每次先重新登录；
    连续 5 只失败就停（日志写 STOPPED）。过一会儿重跑同一条命令，已取完的不会重取。
  - 报“用户未登录”（10001001）：机器上有另一个 Baostock 进程登出了同一个匿名会话。同一时间只能有一个 Baostock 进程；确认后重跑。
  - 速度明显下降（每分钟从二十多只掉到十只以下）：Ctrl+C 停掉，加 --relogin-every 100 重跑。
  - AssertionError “end … is later than the last day Baostock has finished loading”：把 --end 改成前一个交易日，或等到本地时间 02:00 以后。
  - AssertionError “a resumed run must use the same range and code list”：续跑时改了区间或代码表。恢复原参数；确要换区间，换一个 --out 目录从头取。
  - AssertionError 出在 rs.fields 或 “raw and qfq dates differ”：接口行为与脚本假设不同。停下交回，不要绕过。
  - 第 3 步 “the fetch is not complete”：回第 2 步跑到 COMPLETE。
  - 第 3 步 “the overlap days are not exactly the last days of the old panel”：交易日历与旧面板对不上（缺日或旧面板不是到 2026-10-09 的那份）。交回。
  - 第 3 步 NOT CLEAN 且不同的单元格几乎都在“新数据标为不可交易”的行上：说明旧面板对停牌日的记法与本脚本不同
    （本脚本：tradable = tradestatus 为 1，价格照 Baostock 原样保留）。这是映射规则问题，交回由协议方定，不逐只打补丁。

七、需要研究者知道的事
  - 要联网两次：装包一次（PyPI），取数一次（Baostock 服务器）。取数约 2–3.5 小时，期间机器不能休眠或断网；断了可以续跑。
  - 占用：一个 Python 进程，单线程，BelowNormal 优先级，内存不到 100 MB，CPU 几乎都在等网络；机器可以照常使用。
    它是运行超过 30 秒的 Python 进程，按计算名额规则算占一个名额。
  - 磁盘约 30 MB，全部在本目录的 pylibs\ 和 data_new\ 下。
  - 取回的只是公开行情；得到的新日子从 2026-10-12 起（到 2026-11-09 约 21 个交易日），是此后唯一没被任何人看过的数据。
  - 2024-06-28 以后上市的股票不在代码表里，延伸段里没有它们；方案的股票池要求此前至少 750 个可交易日，它们在 2027 年年中以前进不了池。

八、写脚本时拿不准、运行前要验证的点（代码里都用 “VERIFY BEFORE RUN” 标出）
  1. baostock 的接口名、参数名和字段名（login、query_history_k_data_plus、query_trade_dates；字段 date,code,open,high,low,close,preclose,volume,amount,turn,tradestatus,isST；
     adjustflag 3 = 不复权、2 = 前复权）是凭记忆写的。第 1 步专门验证这一点。
  2. 成交量单位（股）、换手率单位（百分数）、preclose 是否为除权参考价：第 1 步的 CHECK 2、CHECK 4 和第 3 步的重叠日核对共同验证。

  4. Baostock 的入库时间（17:30、18:00）是凭记忆写的；保险起见 --end 取前一个交易日也可以。
  5. 2026-09-25 休市是按“旧面板 08-24 至 10-09 共 29 个交易日”推出来的，没有查交易所日历；以第 1 步打印的交易日历为准。
